# Map Editor — creative mode extension hooks

## Overview

Reserved extension points shipped with map editor v1 for [creative-mode.md](../../design/creative-mode.md) Phase 2. The Scripts tab's three sub-tabs (Spawn Points, Rooms, Starting Air) have authoring UI; the remaining reserved hooks are unselected.

Opening the editor pauses no simulation (tech-debt P2.2, plan Decision 10: only map load, clear and import take a `WorldSimSuspension` scope). It calls `ApplyEditorVisualSuppression`: health/atmos/hit/blast screen feedback is hidden and the atmos fullscreen passes plus wind streaks stop drawing. Closing restores both; the static atmos flag is also cleared in `OnDestroyed` so a scene unload cannot latch it.

Unsaved-change tracking (A4): `MapEditorUndoStack` keeps revision-based save points through undo/redo,
branches and the bounded history. Successful persistence saves/loads set the template identity
(`EditingTemplateName`) and save point; a failed save keeps the edits unsaved, and a new empty map
starts unsaved. Round stop uses this to prompt or autosave before unloading; see [rounds-lobby](rounds-lobby.md).

Object setup ([object-setup-persistence](../2026-11_object-setup-persistence.md)): saved maps keep each object's device settings, locks and container contents. Delete, move and replace undo carry the setup (`RemovedTileRecord.Setup`, `ClearResult.Setup`); the Dropper asks the server for the picked object's setup (`RpcCaptureDropperSetup`), and later places of that asset carry it in `MapEditorCommandDto.Setup` until a palette pick clears it (`MapEditorSetupCopy`, 64 KB cap per submit, refused not truncated). The server knows who has the editor open (`RpcSetEditorOpen`); for them, an interaction step (`ServerInteractionSteps`), a machine-panel control or an inventory move that changes a placed object's setup becomes a `SetObjectSetupCommand` they own (`MapEditorSetupTracker`), so Stop prompts and undo reverts it. Locker lock/unlock skip the ID check for them. Sandbox rules and the rate limit look inside a copy's nested contents.

## Start here

Spawn Points authoring (**Scripts → Spawn Points**):

- Catalog: `spawn:job:{RoleName}` / `spawn:antag:{Category}` (`MapEditorSubcategory.SpawnPoints`, flagged `SandboxRestricted`). The palette lists only `MapEditorSpawnCatalog.MarkerAntagonists` (Nuclear Operatives); the enum keeps Traitor and Malf AI so old records still load
- Registry: `TileSubSystem.SpawnPoints` (`SpawnPointRegistry`); one marker per tile
- Persist: `SpawnPointPersistenceContributor` (`spawn-points` station-template chunk)
- Effort: [2026-07_spawn-point-authoring](../../archive/architecture/2026-07_spawn-point-authoring.md)

Gas markers authoring (**Scripts → Starting Air**, [atmos-machinery](../../plans/atmos-machinery.plan.md)):

- Catalog: `gas-marker:{Kind}` through `MapEditorGasMarkerCatalog`: gas source, line fill, room air
- Registry: `TileSubSystem.GasMarkers` (`GasMarkerRegistry`); one marker per tile, whatever its kind. `GasMarkerRecord` holds kind, position, line, pressure and gas fractions, and is the saved, wire and command shape alike. Unlike spawn points it syncs to clients (`TileSubSystem.GasMarkers.cs`), so remote editors see pins and can delete
- Persist: `GasMarkerPersistenceContributor` (`gas-markers` station-template chunk)
- Form: `UI/MapEditorGasMarkerView.cs`. Picking a kind opens it on `MapEditorViewModel.GasMarkerDraft`, which placement reads, so placing needs no Apply. Select opens a placed marker with **Apply to marker**; Dropper copies one into the draft. The Move tool doesn't move markers
- Pins: `MapMarkerEditorView` draws spawn and gas markers under the Scripts layer
- Runtime: [atmospherics](atmospherics.md) `AtmosGasMarkers`

Area metadata: `MapEditorArea.cs` adds `MapEditorPermissions.TryAuthorize`-gated inspect/apply RPCs and server undo/redo; `UI/MapEditorAreaView.cs` edits the selected room. Names, department tags and explicit access masks persist through the existing area contributor. Room editing is selected through **Scripts → Rooms**. Its palette uses the standard Construct/Select/Dropper/Delete toolbar; New room is a distinct + palette entry, with numbered room names and creation/first stroke grouped in undo. Scripts markers default off and follow entry/exit of the Scripts category. `MapEditorAreaOverlay` renders the synced area membership with the gizmo color palette (one mesh per chunk; Resources shader). Areas is off by default in Layer View Mode, enabled by Scripts → Rooms across its existing toolbar tools and hidden on other tabs/editor close. Room and layer controls reuse `MapEditorView.SwitchRow`. Department mode previews read-only access bits and retains the custom override. Areas also shows UI Toolkit room-name labels anchored on a tile near each room center; names sync through a buffered snapshot and refresh on rename/undo. Painted boundaries, APC-less room creation and reversible line/rectangle strokes are implemented and manually accepted by the owner in the editor ([area-authoring](area-authoring.md)); release dogfood remains A2.5.

Systems views ([map-editor-systems-views](../2026-11_map-editor-systems-views.md), Phases 0–2: shared base, Atmos topology and badges, Atmos tracing): shared types in `MapEditor/SystemsView/` — `NetworkIdentityTracker<TSegment>` (Q3 view ids), `SystemsViewStructure`/`SystemsViewDelta` (structure stream and its per-client delta; a segment carries `Links`, the sides its run really joins, as `SystemsViewLinks` bits), `SystemsViewWire` (custom FishNet format with packed ints, `SizeOf`, `Limit`), `ISystemsViewSource` (one per domain, registered on `MapEditorSubSystem.SystemsViews`, a `SystemsViewPublisher`), `SystemsViewDomains` (each domain registers a `SystemsViewDomain`: its `ISystemsViewStyle` for line offsets, badge drawing and hover words, its legend lines and its own layer; shared code has no domain switches), `SystemsViewMeshBuilder`, `SystemsViewPalette`, `SystemsViewLegend`. `MapEditorSystemsView.cs` holds the hub RPCs (`RpcSetSystemsView`, `TargetSystemsViewDelta`); the server polls watched views every 0.25 s, reads each source's version once per poll, and sends each client only what differs from what it was sent, at most `MaxBytesPerSend` (48 KB) per send: a bigger first open goes out over several polls, labels first. Closing the editor or disconnecting unsubscribes. Client: `MapEditorSystemsViewClient` (applies deltas, `HoverText(tile)`) + `MapEditorSystemsOverlay` (per chunk a run mesh, dark underlay then network colour as half-tile bands toward each link, and a badge mesh one render queue above; a delta rebuilds only the chunks it touches; area-overlay shader). The hover reads through the cursor badge (`ExamineSubSystem.SetCursorLabelOverride`), under the placing label when something is being placed (`MapEditorSystemsViewClient.CursorLabel`). `MapEditorViewModel.ActiveSystemsView`: Gas Pipes → Atmos and Cables → Power by themselves, the right-toolbar toggle pins one from any tab; while on, `IsXRayLayer(view, category)` layers are dimmed (`SystemsViewXRayLayers`, plus the domain's own layer, Gas Pipes for Atmos) and come back by the Lower tabs' rule (`_autoHidden`). The own layer stays first to pick: `MapEditorCursorPick` prefers `IsLayerPickable` layers, which include it. Legend under the left toolbar, scrolling past 300 px, open state in PlayerPrefs `SS3D.MapEditor.SystemsLegendOpen`. Tracing (Phase 2): with a view on, Select also traces (`MapEditorSystemsView.TraceSystemsView`, Q11): the domain style's `TraceTargets` names the picked object's networks and each side ("Inlet", "Back"); when the pick landed on something outside the view (the raycast stops at dimmed floors, tables and walls) it reads the tile under the cursor on the overlay's plane, the view's own layer first (`MapEditorSystemsViewClient.TraceSelect`, `MapEditorCursorPick.TryGetPointedTile` / `TraceLayerOrder`; hover reads the same tile). A trace follows at most `SystemsViewPublisher.MaxTracedNetworks` (4) networks. Automation reaches the hub's input handlers through the internal seam `MapEditorAutomationSeam.cs` (`InternalsVisibleTo` the Lifecycle pilots' assembly), not reflection. `MapEditorSystemsViewClient` keeps the trace (`TraceSides`, `TraceId`, `Live`, `TraceRevision`) and hands the hub `TakeTraceRequest` for `RpcTraceSystemsView`; the overlay dims every other network and badge (`SetFocus`, `SystemsViewMeshBuilder.Alpha`). The server keeps each connection's traced view ids on its `SystemsViewPublisher` subscriber; `PublishLive` (every second poll, 0.5 s) reads `ISystemsViewSource.ReadLive` and sends `TargetSystemsViewLive` (`SystemsViewLive`: rows, devices, `Paused`) only when it changed. A network that goes leaves the trace; the last one going ends it. UI: `UI/MapEditorSystemsTracePanel` (panel `systems-trace` beside the top of the left column, Clear `systems-trace-close`, Locate `systems-trace-locate-<n>`, "Paused" tag, world label `systems-trace-label`), values updated in place so 2 Hz updates keep the scroll. The Atmos source and style live in [atmospherics](atmospherics.md) (`Atmospherics/SystemsView/`); Power has none yet, so that view shows an empty overlay.

Sharing (A5): the Save popover's **Save & Export** saves, then zips the template into `Data/Exports/` on the server's disk (`RpcExportMap` → `MapFileSharing.TryExport`). On a host it opens the file manager with the zip selected and copies its path to the clipboard; a remote client only gets a toast, because the file is on the server. The Load popover's **Open Maps Folder** opens `StationTemplates/` (host only); zips dropped there import on the next list. A Load reports objects this build doesn't have (`TileMap.LastLoadSkipped`). Testers' guide: `Builds/TESTERS.md`, shipped in the release zips.

Open build: only a server launched with `-sandbox` uses `OpenBuildMapEditorAuthorizer` (anyone not Restricted may edit, without becoming admin); every other server is admin-only (`MapEditorPermissions.CreateDefault`). The standalone `-openbuild` switch was removed in tech-debt P1.11. For those non-admin "sandbox players" (`MapEditorPermissions.IsSandboxPlayer`), `MapEditorRateLimiter` throttles edits (4000-operation burst, 400/s refill; `RpcExecuteCommands` and `RpcMoveObject` share one budget). They may only undo or redo when the newest history entry is their own (history entries record their owner's client id), and they can't delete maps or overwrite maps saved by someone else this session (`MayReplaceMapFile`).

Sandbox lockdown ([2026-11_sandbox-server](../2026-11_sandbox-server.md)): `-sandbox` is the one open-build mode. With `MapEditorPermissions.PersistenceAllowed` off (`ServerSettings.MapPersistence`), Save, Export, Load, Delete, New Map and the round-end autosave are refused for everyone. `MapEditorSandboxRules` refuses spawn-point commands and the nuke/disk assets to sandbox players (also on move), but not gas markers, and `RpcSetInvincible` refuses them. On open the server sends a `MapEditorCapabilities` TargetRpc; the view hides Save/Load, the Player Invincible switch, every `SandboxRestricted` sub-tab (Spawn Points; `MapEditorCatalog.IsShown`, so opening Scripts lands on Rooms) and denied palette entries (`MapEditorCatalog.HideSandboxDenied`). Ghosts may edit (the open check only asks for a spawned entity).

Save validation uses `Tile/Validation/MapValidationService` for the server's selected mode after saving. `MapValidator` names palette locations through `MapEditorSubTabs.PathOf` ("Scripts → Spawn Points"); `MapEditorCatalogMappingTests` fails if a sub-tab label is hard-coded in its strings. An issue may carry `EntryKey` (missing spawns, nuclear checklist, missing air alarm, scrubber, vent or APC); Map Check then shows **Show in palette**, which searches `MapEditorCatalog.SearchTermFor(key)` and opens that sub-tab. The key constants live on `MapValidator` and `MapEditorPaletteSearchTests` checks each is in the palette.
Incomplete maps remain saveable; errors and soft warnings open an author-only scrollable Map validation popover
(with no timed dismissal). Unknown job markers, markers without plenum flooring, and devices that cannot do their job are soft warnings: vents or scrubbers with no air alarm (a room with none, or a device outside every room), vents, scrubbers or gas pumps with no pipe on a line they attach to on their own tile, an air alarm facing no room, a room with vents but no scrubbers or the reverse, a painted room whose devices have no APC, a room with more than one APC, a line fill with no pipe on its line, and a gas source or room air marker outside a sealed room (`AtmosRoomFlood`). "Room" means an [area](area.md): one APC's flood fill bounded by walls and doors, or a painted room on an authored map. It is not always one physical room, and APC default names repeat, so these warnings carry a position.
The same policy blocks round Start; see [rounds-lobby](rounds-lobby.md). Validation does not implement job-to-spawn assignment.

## Pitfalls

- **Select's pick hits the dimmed floor, not the pipe under it:** `MapEditorCursorPick.TryPick` raycasts first and takes the first collider, and x-ray dimming leaves floors, furniture and walls with their colliders, so a click over a pipe picks a floor, a table or a wall (on Classic MiniStation, a wall several tiles off at the editor's angle). `TryPickFromLocations` does not help: it honours `IsLayerPickable` but keeps its fixed order, furniture before pipes. The trace reads the pointed tile on the overlay's plane, own layer first; Select itself still acts on what it picked. Hit 2026-11-14.
- **A pilot that calls a handler from `EditorApplication.update` reads the editor's input buffer:** `InputState.Change` on the mouse defaults to the player buffer, so `Mouse.current.position` read synchronously from the editor update is (0, 0) and the pick lands somewhere else, with no error. Point with `InputUpdateType.Editor` before calling `HandleSelectClick` directly (`MapEditorSystemsPilot`). Hit 2026-11-14.
- **Overlay vertex colours wash out to pastel:** the `MapEditor/AreaOverlay` shader outputs vertex colour unconverted, and the project renders in linear space, so a palette colour stored as authored (sRGB) shows far lighter than its legend swatch, with no error. `SystemsViewMeshBuilder.ToStored` converts to linear; anything else drawing palette colours through that shader must too. Hit 2026-11-14.

- **A command that changed nothing must not undo anything:** tile, item and move commands implement `IReportsChange`. A refused place or move and an empty clear report `Changed == false`; `MapEditorCommandService.Execute` then returns false and pushes no undo step, and their `Revert` does nothing (before tech-debt P2.4, undoing a blocked place cleared whatever blocked it, and a blocked move deleted the source). `TryClearTile` reports success on an empty slot, so tile clears read the recorded removals instead; `TryClearItem` reports whether it removed one. `RpcMoveObject` toasts "Can't move that there." on a refusal.

- **In-world changes land a frame after their RPC:** `InteractionSource.Interact` only queues an interaction; its `Start` runs in the source's next `Update`. Snapshotting setup around `CmdRunInteraction` saw no change and recorded nothing. Track around the step itself (`ServerInteractionSteps.Wrap`, installed only while someone has the editor open). Hit 2026-11-14.
- **No in-world interaction with the editor open:** the MapEditor input context masks Interactions, so setup is set while playtesting (editor closed) and caught by the next save; the editor-open tracking and lock bypass only fire through server paths today. An in-editor Use tool is a follow-up. Owner decision 2026-11-14.
- **A new item is missing from the library with no error:** the palette and saved maps only see assets under `Content/Data/TileMap/Resources`, so a prefab with an `ObjectAssetReference` but no `ItemObjectSo` works in play and cannot be placed. An item missing from the baked `MapEditorCatalog.asset` is inferred at runtime without its asset path, so it lands in Items › Misc, not its folder's sub-tab, until the catalog is regenerated. `AssetAudit.TileMapTests` checks this for `Items/Weapons/` only. Hit 2026-11-06 (C4, X4, energy weapons).
- **A form test sees no edits outside a live panel:** UI Toolkit fields raise `ChangeEvent` only when attached to a panel, so `view.Build(new VisualElement())` passes the build and silently drops every edit. Host the view in an `EditorWindow`, as `GasMarkerAuthoringTests` and `MapEditorAreaViewTests` do. Hit 2026-11-05.
- **The gas marker form closes itself off its sub-tab:** `RebuildGrid` closes it whenever the sub-tab isn't Starting Air, and any view model change can rebuild. A test must select Starting Air first or the form is gone by the next query. Hit 2026-11-05.
- **Room form shows blank labels / default white controls:** runtime panels do not inherit the Editor theme; the room form needs an explicit font, text colors and field/input styles in `MapEditor.uss`. Use stacked labels and bounded scrolling; toolbar tools need baked icon references.
