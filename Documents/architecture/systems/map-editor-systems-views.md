# Map Editor — systems views (Atmos and Power)

## Overview

The Map Editor's **Atmos** and **Power** views ([creative-mode.md](../../design/creative-mode.md) §4 "Seeing what's connected"): every pipe network or cable circuit in its own colour, device badges, a Select trace with live numbers, red problem markers that Map Check also reports, an admin pause and step, and the Atmos view's Room air. Gas Pipes turns Atmos on and Cables turns Power on; the view tools' toggle (top left) pins one from any tab. While a view is on, its x-ray layers dim. The contracts below are cited from code by their bold names.

- **Server-authored.** The server computes network identity, colours, device state and problems, and sends them only to clients with the editor open. Clients never rebuild topology from their own tilemap: problems must match the server-authored Map Check, and host play hides client reconstruction bugs.
- **Streams.** *Structure* (segments → view id, labels, badges, markers, rooms) is polled every 0.25 s while someone watches a view, and each client gets only what differs from what *it* was last sent (`SystemsViewDelta`), at most `MaxBytesPerSend` (48 KB) a send: a bigger first open goes out over several polls, removals and labels first. *Live* numbers go only to the client tracing a network, re-read every 0.5 s right after a structure publish and sent only on change. Clients without the editor open get nothing.
- **View ids.** `NetworkIdentityTracker<TSegment>`: after a rebuild, each new network takes the id of the old one it shares the most segments with (ties go to the lower id); others get fresh ids. The id picks the palette colour and the label ("Supply 3", "Circuit 2"), so colours stay put through edits. A network may name a hue (`SystemsViewNetwork.Family`): the id then picks a shade of it. Atmos networks take their line's (`AtmosSystemsViewCodes.LineHue`: Supply blue, Waste red, like the pipes' paint, Mixed green, Surface amber); Power uses the whole palette. Power rooms are networks too, at `PowerSystemsViewCodes.RoomViewIdBase` (2^20) + area id.
- **Code split.** Each domain keeps its source, analyzer, codes and client style under `Atmospherics/SystemsView/` and `Electricity/SystemsView/` behind `ISystemsViewSource` (server) and a registered `SystemsViewDomain` (client: `ISystemsViewStyle`, legend lines, own layer). Shared code in `Tile/MapEditor/SystemsView/` has no domain switches. Transport is a partial of `MapEditorSubSystem` on the existing hub; no scene or prefab edits. New RPCs bump `ProtocolVersion`.
- **Drawing.** Client-local per-chunk meshes with the area overlay's Resources shader: runs as half-tile bands toward each real link over a dark underlay; badges and markers as quads in one badge mesh per chunk a render queue above. Room tint is a second `MapEditorAreaOverlay` with a tint (queue 3999), Room air another overlay (3998). UI Toolkit draws the toggle, legend, trace panel, sim bar and labels; no Gizmos, no IMGUI. The sim bar and legend sit under the camera column (top right); the trace panel floats beside the view tools (top left), a one-line row per device (name, room, state) that locates it on click.
- **Tracing.** With a view on, Select both traces the picked object's network(s) and opens its setup as usual; a bare pipe or cable only traces. A trace follows at most `SystemsViewPublisher.MaxTracedNetworks` (4, a manifold's lines). A network that disappears leaves the trace; the last one going ends it. A floor tile traces the cable under it, else (Power) its room.
- **Problems.** One pure analyzer per domain (`AtmosProblemAnalyzer`, `PowerProblemAnalyzer`) behind `ISystemsViewSource.Analyze()`. Its issues are both the view's markers (`SystemsViewMarker.IssueId`) and Map Check warnings with Locate, never a round-start block (round start passes `includeSystemsViews: false`). Each kind has a `Name` and number-neutral `Words`; the legend line is `Name: Words.` and every Map Check body contains the same words. The analysis re-runs only when something it reads changed, never on a switch or status flip, so markers don't flicker. A source whose state lags the map (`AnalysisCurrent` false) reports nothing; Map Check resends that client's report once every source is current (`AwaitSystemsForValidation`).
- **Pause and step.** `RpcSystemsSimulation` pauses and steps the server's atmos and electricity channels (`ISystemsViewSimulation`) for an editor user who is the host or an Administrator, never a sandbox player (`MapEditorPermissions.MayControlSimulation`). It holds only channels it paused itself. A step is one counted tick of each channel (`SimulationChannel.Step`). The pause lifts, resuming only what it held, when its admin's editor closes or they disconnect, the round leaves Ongoing, the server stops, a world suspension starts, or a simulation runs again under it (`Reconcile`). A pure client's own electricity channel is never touched. Everyone in the editor sees PAUSED; only admins see the controls.
- **Room air.** A sub-toggle with the Atmos view on, off by default and reset when the editor closes. `MapEditorRoomAirOverlay` tints simulated floors in 64 steps of 4 kPa (`AtmosRoomAirPalette`) from the atmos snapshot's CPU copy, so the editor's render suppression stays on. Turning it on resends that client every atmos chunk once (`AtmosChunkResync`); on a host it widens the atlas to the whole station (`AtmosSubSystem.SetRoomAirRequested`).

**Deviations from design and the original plan** (kept on purpose):

- Badges and markers are quads in a per-chunk mesh, not instanced: the area overlay shader has no instancing path and a few hundred badges cost one draw per chunk.
- The Atmos view dims the real pipes to the x-ray alpha rather than covering them, because overlay offsets can't match pipe meshes; the own layer stays first to pick.
- The trace panel floats beside the view tools (top left), and the legend and sim bar sit under the camera column (top right): in the view tools' column they would stretch its cells to their width, and there is no room for all three above the library at 1080p.
- The open-end marker says "the pipe stops here, joined to nothing", not creative-mode §4's "gas leaks out here": the simulation doesn't leak gas at a pipe end today.
- Room air reads the CPU snapshot instead of lifting `AtmosRenderContext.SetRenderingSuppressed` for a pressure pass: no such pass exists (the fog, glow and distortion are what the editor hides). The atmos chunk broadcast still reaches every pure client; only the one-off resync is gated by the toggle.
- Map Check's "device on no pipe" (`pipe:*`) and "No APC" (`no-apc:*`) rows moved into the analyzers: `no-apc` is now category Power and fires for a room with any registered power consumer but no APC, so a room with only meters, injectors or manual valves no longer warns.
- `ElectricityDebugGizmoDrawer`, `ElectricitySubSystem.Debug.cs` and `ElectricityDevSettings` are gone; the Power view replaces them. The F1 `AtmosDebugController` stays for dev-only turf inspection, gas spawning and region waking.

## Extension points

- **A new view** (disposals is the next one, creative-mode §15): add a `SystemsViewKind`, a source implementing `ISystemsViewSource` (and `ISystemsViewSimulation` if it has a channel to pause), offered to the hub with a `SystemsViewRegistration` from the domain's server tick, and a `SystemsViewDomain` registered on load with its style, legend lines and own layer. Keep the domain's wire codes in its own `*SystemsViewCodes`: never renumber, only add.
- **A new problem kind:** add a `SystemsViewProblemKind` (a code for the marker slot's high five bits, `Name`, `Words`) in the domain's analyzer, keep the analyzer pure (fill its input from the source), give it a fixture in its analyzer tests, and make sure whatever it reads moves the source's analysis version. Ids are `<kind>:<x>:<y>` or `<kind>:<area>`, identical in Map Check and the marker.
- **Atmos and Power issue ids:** `open-end:<line>:<x>:<y>`, `pipe:<Vent|Scrubber|GasPump|Valve|ThreeWay|LineReader|LineFill>:<x>:<y>`, `no-source:<x>:<y>`, `no-sink:<x>:<y>`, `atmos-power:<area>` (category Atmos); `apc-cable:<x>:<y>`, `circuit-source:<x>:<y>`, `circuit-demand:<x>:<y>`, `no-apc:<area>`, `smes-circuit:<x>:<y>` (category Power). The rules (what counts as a source or sink, rated supply against rated demand) are in each analyzer's summary.
- **An admin-only editor action:** gate it like `MayControlSimulation`, and list its ServerRpc as `AuthorityCheck.Admin` in `ServerRpcAuthorityAuditTests`.
- **Open questions:** an admin toggle for the views in normal rounds, and in-world scanners, need design in `atmospherics.md` and `electricity.md` first ([map-authoring](../../milestones/map-authoring.md) **Explicitly deferred**). A gas meter's line choice ([#280](https://github.com/henkhooft/SS3D/issues/280)) asks the same "which line is this device on" question as the Atmos hover readout (`AtmosSystemsViewStyle`).

## Pitfalls

- **`MapEditorPermissions.TryAuthorize` is not an admin check:** the open-build authorizer (`-sandbox`, and `mppm:systems-view`'s `editor_for_clients`) lets every non-Restricted player in. An editor action only admins may take must check the role itself (`MayControlSimulation`: authorized, and host or Administrator via `HostOrAdministrator`), or every builder on an open server gets it.
- **Select's pick hits the dimmed floor, not the pipe under it:** `MapEditorCursorPick.TryPick` takes the first collider, and x-ray dimming leaves floors, furniture and walls with their colliders. `TryPickFromLocations` honours `IsLayerPickable` but keeps its fixed order, furniture before pipes. The trace reads the pointed tile on the overlay's plane, own layer first; Select itself still acts on what it picked.
- **A pilot that calls a handler from `EditorApplication.update` reads the editor's input buffer:** `InputState.Change` on the mouse defaults to the player buffer, so `Mouse.current.position` read from the editor update is (0, 0) and the pick lands elsewhere, with no error. Point with `InputUpdateType.Editor` before calling `HandleSelectClick` directly (`MapEditorSystemsPilot`).
- **Overlay vertex colours wash out to pastel:** the `MapEditor/AreaOverlay` shader outputs vertex colour unconverted in a linear-space project, so an sRGB palette colour shows far lighter than its legend swatch. `SystemsViewMeshBuilder.ToStored` converts to linear; anything else drawing palette colours through that shader must too.
- **A nested type counts toward its holder's class-size cap:** `ClassSizeRatchetTests` adds a nested type's lines to the class that holds it. The Power source's poll state lives in top-level types (`PowerSystemsViewSeen.cs`) and the Power pilot is its own class for that reason.
- **Right after a template load the networks aren't rebuilt:** the power graph rebuilds a tick later (`CircuitOf` answers null until then, which reads as every APC and SMES on no circuit) and atmos may not be ready. Anything reading a source's problems must honour `AnalysisCurrent`, not treat an empty list as clean.
