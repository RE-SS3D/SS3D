# Entities

## Overview

Humanoid/silicon entity spawning, minds, and join/round ordering with [rounds-lobby](rounds-lobby.md). Humanoid body animation is driven by a packed `BodyAnimationSnapshot` SyncVar, not ad-hoc Animator calls.

**Prefab composition:** Human remains a large shared graph. Evolve it through the
[Entity prefab recipes](entities-prefab-recipes.md); remaining structural work is tracked in
[TECH_DEBT §1.1](../TECH_DEBT.md#11-humanprefab-mega-prefab).

**Body presentation:** `Ragdoll` owns replicated `BodyPresentationState` (`Locomotion` / `Collapsed` / `Dead`) and is the sole applier. Movement, bridge, and orchestrator read `Presentation` — do not invent a parallel collapse path ([2026-07_body-presentation-authority.md](../../archive/architecture/2026-07_body-presentation-authority.md), shipped).

## Extension points

- Stance packs: Peaceful (Locomotion), Melee (Pro Melee Axe locomotion; run strafes and swings from Pro Sword and Shield), Ranged (Basic Shooter), Injured (Male Injured Pack). Rebuild after reimporting Mix_* clips (`SS3D → Animation → Rebuild Combat Stance Blend Trees`).
- Shelved clips (not wired): most of `Assets/Art/Animations/Misc/` and `Assets/Art/Animations/Probably Not/` — future collapse / cough / crawl / drag / fall; **exceptions:** `Mix_Floating` (space float + ghosts); `Mix_GettingHit` (Peaceful/limp Flinch).
- Hit flinch: `HumanHealthController.ApplyDamage` (brute ≥ `BloodSprayMinBrute`, presentation Locomotion) → `HumanoidCombatController.OnHitReceived` → `ApplyStagger` + `Flinch` (one packed publish). Base selects by `LimpSide` / `CombatStance` — GettingHit (limp or Peaceful), gut (Melee), `Mix_HitReaction` (Ranged). Additive layer also takes `Flinch` → gut with a **lerped** weight (~0.75) while Staggered. `Mix_ShoulderHitAndFall` / get-ups deferred.
- Ranged fire/reload: `RequestAttack(FireRifle|Reload)`. Upper Body stays weighted for the whole Ranged stance on **Rifle Aim Idle** (`Mix_AimingIdle`); Fire/Reload oneshot and return there. Orchestrator CrossFades to Aim Idle on Ranged enter (Hold Weapon had no path otherwise). Base Ranged FreeformCartesian keeps foot phase — do not pulse Upper Body weight per shot.
- `HumanoidCombatMode` is 2 bits; **`F` toggles Help/Harm intent** (combat stance follows Harm via `InteractionController` / `InputSubSystem.ToggleIntent`). Inventory picks Melee vs Ranged while in combat (`RangedWeaponItemExtension` preferred over trait name match). `LimpSide != 0` → Injured locomotion; `InjuredLeg` drives idle severity + additive weight.
- **Animator vs code:** swing exit times, limp transitions, masks are animator-owned ([animation-polish](../../archive/architecture/2026-07_animation-polish.md)). Code sets parameters/triggers and look-at only — no swing duration constants.
- **Ragdoll gravity:** `Ragdoll` checks support at the hips while down; unsupported bones disable gravity and discard downward settling velocity. Returning to a plenum restores gravity. Root alignment only snaps to nearby floor under supported bodies.
- **`IsRunning` is the effective gait:** `HumanoidLivingController` overrides it to false while magboots hold. The player's run toggle survives underneath, so sprinting returns when the boots let go.
- **Collapse / death:** write `Ragdoll.ServerSetPresentation` (or wrappers); readers use `Ragdoll.Presentation`.
- **Space float:** living bodies — confirmed no plenum (`Unsupported`) → `SetFloating(true)`, skip gravity/WASD, coast. Client AOI lag / incomplete plenum (`Unknown`) must not enter float; skip gravity only while no physical floor collider is underfoot (raycast), then resume normal loco so spawn is not soft-locked when the map is visible but occupancy is still Unknown. Keep coasting only if SyncVar already Floating (deep space). Server occupancy-miss is Unsupported only after `TileMapLoaded`; `ServerReconcileSpaceSupport` clears Floating while Unknown and packs it for remotes. A remote client cannot see `Unsupported`, so `HumanoidLivingController` keeps the last supported frame's velocity and adopts it when Floating arrives first (`ResolveCoastVelocity`). **`HumanoidPredictedMovement` is disabled on `Human.prefab`**; `HumanoidLivingController` owns the live path. Ghosts still set Floating on spawn.

## Pitfalls

- **Wind must reach the physics authority:** server transforms do not simulate living owners’ bones. Send wind velocity to the owner; server applies corpse/unowned wind physics. Upright drift runs owner-side because `HumanoidPredictedMovement` is disabled on `Human.prefab` (enabling it means moving wind into the replicate step). For an unowned upright body the server enables its `CharacterController` only for the `Move` call: left on, it adds a capsule to server raycasts and blocks teleports. Never convert a health-owned timeless collapse into a timed wind knockdown.

- **Critical rejoin T-pose:** ownership changes do not change presentation. `Ragdoll.OnOwnershipClient` must reapply collapsed/dead presentation so the new owner simulates bones and observers stay kinematic. Initial SyncVars may collapse before `OnStartNetwork`; preserve the original NetworkAnimator enabled state instead of recapturing its suppressed value.

- **Spaced ragdolls falling below the deck:** dynamic bones must update `useGravity` from plenum support, including after death transfers physics to the server. Unknown client occupancy preserves known Floating or probes nearby floor; never use an unlimited alignment ray or count bodies/items as floor.

- **Remote client stops dead at the ledge:** a pure client never reads `Unsupported` (client AOI returns `Unknown`), so the server's Floating SyncVar arrives first and `TryProcessSpaceFloat` reached the coast branch with a zero `_coastVelocity`. Keep `_lastGroundedVelocity` from supported frames and adopt it when already floating with no local capture. Hit 2026-11-04 (#124).
- **`AlignToHips` keeps the previous root Y when support is known but the floor ray misses:** otherwise the root would stay at hip height with nothing pulling a recovered body down. Only unsupported bodies follow the hips. This does not explain the server/client height offset in #127: for a living owned body `AlignToHips` runs on the owner, not the server (`IsRagdollPhysicsAuthority`). The offset did not reproduce on a dedicated server after collapse and recovery or while floating (2026-11-04); #127 stays open.

- **Critical movement:** the living movement loop also checks health presentation intent and clears pending movement when incapacitated; do not rely on component disabling alone (Coimbra update subscriptions can still fire).
- **Ranged fire resets feet / snaps every shot:** FireRifle + Reload must stay on **Upper Body** (mask excludes hips/legs) — Base oneshots restart FreeformCartesian and pop foot phase. Keep Upper Body **weighted for the whole Ranged stance** on **Rifle Aim Idle**; oneshots return there. Pulsing layer weight 0→1→0 per shot (or exiting into Hold Default) is the arm snap/twitch.
- **Remote fire/reload never plays:** `CmdFireTrigger` / stagger must `ApplyLocalSnapshot()` (pack `ActiveTrigger`) **before** `_triggerSequence++`. SyncVar OnChange rebuilds from the old pack synchronously and otherwise wipes the trigger — owner still sees local prediction.
- **Weird pose until first shot after entering Ranged:** a held gun parks Upper Body on **Hold Weapon**; that state must transition to **Rifle Aim Idle** when `CombatStance == Ranged` (also Hold Item/Default). Orchestrator CrossFades to Aim Idle on Ranged enter as a belt-and-suspenders.
- **Corpses and Minds outlived every round:** at death the ghost replaces the body in `_spawnedPlayers`, so `DestroySpawnedPlayers` never saw the corpse; and `TryCreateMind` spawns a Mind per spawn that nothing despawned (`_spawnedMinds` is never filled, so `HasMind` is always false). Round end now despawns tracked corpses and each spawned player's Mind. Found by `reset-health.jsonl` (+1 NetworkObject per player per round); the sandbox pilot asserts no Human and equal NetworkObject counts across resets.
- **Death logged errors:** `SwapMinds` called `SetFirstObject` on the corpse's invalid (-1) owner after `SetMind(null)`; and `RpcDestroyComponents` could not remove `InteractionController` because `CombatInteractionNetwork` requires it (it is disabled instead). Killing a body in the same frame it spawned also throws in `HumanoidLivingController.OnStartClient`; pilots wait ~2 s before killing.
- **Killed combat dummies stay standing:** `Human.Kill` must call `Ragdoll.ServerDeathRagdoll` itself, before the ghost hand-off. Mindless bodies (`spawndummy`) are never in `EntitySubSystem._spawnedPlayers`, so `TryTransferEntity` fails and a death ragdoll applied only inside `BecomeGhost` never runs — the corpse keeps its kinematic bones. `Kill` also early-returns before instantiating a ghost when `Mind` is null or `Mind.Empty`; there is no player to transfer. The same ownership gap freezes a *living* collapse: `Ragdoll.IsRagdollPhysicsAuthority` falls back to the server when `Owner` is invalid (observers stay kinematic).
- **Ghost spawn stack-overflow:** `HumanoidGhostController.OnAwake` must call `base.OnAwake()`, never `base.Awake()`.
- **`SetMind(null)` must `RemoveOwnership()`:** death `SwapMinds` assigns the ghost's empty mind to the corpse. Leaving FishNet Owner on the corpse delivers corpse TargetRpcs (hit flash) to the ghost — see [health](health.md). Server still `AlignToHips` on death ragdolls; do not write `IsFacingDown` (ServerRpc setter) without ownership — use a local facing bool.
- **Do not redeclare `_bodyStateMachine` on `HumanoidGhostController`:** field already on `HumanoidController`; use `BodyStateMachine` from the base.
- **Walk cycle while “collapsed”:** Coimbra `UpdateEvent` keeps firing after `enabled=false`; limp bridge can still publish snapshots. Applier must `SetPosingSuppressed`; readers early-out on `Presentation != Locomotion` — see [body-presentation-authority](../../archive/architecture/2026-07_body-presentation-authority.md).
- **Remote ragdoll twitches:** observers must stay kinematic while bone NetworkTransforms receive. Only owner (living knockdown) or server (death corpse) runs non-kinematic physics + AlignToHips. Do not `CharacterController.Move` while presentation ≠ Locomotion.
- **Remote CharacterController must stay disabled:** client-authoritative NetworkTransform cannot move the server transform while CC is enabled (teleports are ignored). Keep CC on only for `IsOwner`; otherwise server-side proximity (airlocks) never sees remotes. Hit 2026-07-26.
- **Reclaim must fire `LocalPlayerObjectChanged`:** `TryReclaimEntity` restores ownership without Mind SyncVar change. `Entity.OnOwnershipClient` invokes the event so HUD/lobby leave the menu — see [player-control](player-control.md). Hit 2026-07-26.
- **`Ragdoll.OnDisable` must not `Recover()`:** ownership/network teardown would stand a corpse back into locomotion.
- **Timed knockdown from server:** call `ServerRecover`, not `Recover()` (ServerRpc is a no-op from server).
- **Melee swing torso fight:** Upper Body mask must include spine/chest; head stays unmasked for look-at. Do not reintroduce C# swing duration timers — use AttackSwing + `AttackVariant` (0–2: horizontal / downward / backhand).
- **Swing strike lands at connect:** `MeleeSwingAnimation.Variants` is the single table for swing clips (file, trim frames, strike frame). The rebuild imports and trims the FBXs from it. `AnimationOrchestrator` sets `AttackRate` (swing state speed) so the strike frame plays at the weapon's effective windup, then sets it back to 1 for the follow-through. The windup rides the snapshot (`AttackWindup`, 5 bits, 20 ms steps) so observers match the owner. Long full-body clips (the axe swings struck at ~1 s against 0.2–0.35 s windups) make the target flinch before the arm moves. New swings must strike within 2.5× of the shortest windup (`MeleeSwingAnimationTests`). Swings exit straight to Hold Item / Hold Weapon / Hold Default by `ArmHold`.
- **Left-hand Mixamo mirror:** Upper Body Hold* / Attack Swing* use `MirrorUpperBody` (`Hand.Side`). Do not mirror Base Layer FreeformCartesian — that flips strafes. Set `_side` on `HumanHandLeft`/`HumanHandRight`, not mega `Human.prefab`. Two-hand rifles (`RequiresBothHands`) force `MirrorUpperBody=false` via `TwoHandedWeaponRules` even when the left hand is selected.
- **Every body part is its own nested `NetworkObject`, not a flat component list:** `HumanTorso`/`HumanHead`/each limb prefab under `HumanBodyParts/` carries its own `NetworkObject` with `IsNested = true`. The root `NetworkObject`'s `_networkBehaviours` flattens across those nested boundaries (it lists behaviours living inside body-part prefabs directly). A recipe tool that reuses `StorageContainerPrefabSetup`-style behaviour collection (which stops descending at any child with a `NetworkObject`) will silently drop every nested body-part behaviour from the rebuilt list — only stop at a child Nob when `!IsNested`. See `HumanPrefabHygiene.CollectNetworkBehaviours` ([Entity prefab recipes](entities-prefab-recipes.md)).
- **Stale `m_Script` on stripped nested-prefab mirrors is cosmetic, not a broken reference:** a `stripped` MonoBehaviour placeholder's authoritative type comes from `m_CorrespondingSourceObject` in the source prefab, not its own cached `m_Script` GUID — the cache can go stale (and even reference a since-deleted class) after the source prefab's component type changes without Human.prefab being resaved in the Editor. Fix by updating the cached GUID to match the source's current type; do not delete the stripped block — it is a live entry in the root `NetworkObject`'s `_networkBehaviours` array and deleting it (versus correcting it) shifts every subsequent behaviour's index.
- **Editing a nested body-part prefab asset directly leaves `Human.prefab`'s own mirror of it stale:** running a recipe that destroys a component on `HumanHead.prefab`/`HumanTorso.prefab` (e.g. `BodyPartContainerInteractiveStrip`) does not retroactively update `Human.prefab`'s stripped mirror of that instance — that only refreshes the next time `Human.prefab` itself is reloaded and resaved. `HumanPrefabRecipes.RunAllMenu` always calls `HumanPrefabHygiene.ResyncNestedPrefabInstances()` last, regardless of what the other recipes changed, specifically to converge this. Any new recipe that removes a component from a nested body-part prefab must trigger the same resync.
- **Injured oneshots:** Jump / Turn90 / Emote while limping → Injured Jump / Turn / Wave (Base Layer); healthy oneshots require `LimpSide == 0`. **Jump/Turn90 are not bound in `Controls.inputed`** and nothing calls `PlayLocomotionTrigger` yet — presentation only.
- **One locomotion ramp (M1m):** `HumanoidController.MoveMovementTarget` ramps `TargetMovement` linearly (`_accelerationTime` 0.1 s to run, `_decelerationTime` 0.08 s to stop) and the living path publishes that eased magnitude as VelX/VelZ, so world speed and the blend move together. `AnimationOrchestrator` applies owner values directly and only smooths remotes (`_remoteLocomotionLerp`). Do not reintroduce an exponential `Lerp` in either place: two stacked lerps were the ~1 s "sluggish" ramp and the stop slide.
- **Combat blend trees are Directional and calibrated (M1m):** Melee and Ranged base trees are `FreeformDirectional2D` with samples only on the walk (0.3) and run (1.0) rings — Ranged uses the 8-direction **Pro Rifle Pack** (`Assets/Art/Animations/Pro Rifle Pack`, `Mix_ProRifle*`). `HumanoidLocomotionBlendSetup` sets each child's `timeScale` so clip root speed × avatar `humanScale` equals the gait's world speed, read from `Human.prefab` (`_movementSpeed`, `_combatWalkSpeedFactor`, `_combatRunSpeedFactor`). Rerun **SS3D → Animation → Rebuild Combat Stance Blend Trees** after changing any of those, or feet slide again. Do not put pure-strafe clips at corner positions: in a directional tree a corner means diagonal. Melee's run strafes come from Pro Sword and Shield Pack (`run left/right.fbx`); the arms never show because Upper Body is weighted in melee. The rebuild deletes the previous generated BlendTree sub-assets first, so rebuilds no longer pile up orphans in the controller.
- **Each gait's world speed matches its clip:** `HumanoidLivingController.GaitSpeedFactor` scales `_movementSpeed` (5). Peaceful walk is unscaled (1.5 m/s; `Mix_Walking` is authored at 1.57). Peaceful run uses `_peacefulRunSpeedFactor` 0.8, giving 4 m/s (`Mix_Running` is authored at ~3.9; at 5 m/s it slid and looked too fast). Combat uses `_combatWalk/RunSpeedFactor`. Stamina drain reads the gait value, not world speed, so the factors don't change the sprint budget. Check a clip's authored speed with `AnimationClip.averageSpeed` before you tune a factor.
- **Rifle aim drifts with locomotion hips:** the Upper Body mask overrides spine and arms, but in muscle space they ride on the Base layer hips, and the Pro Rifle walks twist and tilt the hips along the travel direction, so the gun pointed off target while moving and snapped back on stopping. `HumanoidIkController.LateUpdate` corrects after animation: in Ranged stance it rotates spine (40 %) and chest (60 %) so the wielded weapon's `GetMuzzleWorldPose` forward points at the aim point (owner mouse point; remotes rebuild from synced yaw/pitch), faded out during Reload. The correction is split into yaw about world up (capped 35°) and pitch about body right (capped 60°), smoothed at 14/s: a free-axis `FromToRotation` rolls the torso near 180°, and an uncapped instant yaw made a fast mouse flick snap the torso ahead of the slower combat body turn. It needs `Muzzle` forward to be the barrel direction (M4: item −Y). Hit 2026-11-03.
- **`LocoRate` scales locomotion playback:** all four base locomotion states use the `LocoRate` float (default 1) as speed multiplier; `AnimationOrchestrator` writes `HumanoidController.LocomotionPlaybackRate` (living: the exertion movement factor from the synced `ExertionPenalty`), so exhausted feet slow with the body on every peer. A 0 default would freeze animators that never set it.
- **Remote strafes replicate VelX/VelZ:** `HumanoidBodyStateMachine` syncs body-local `_movementVelX` / `_movementVelZ` (snapshot `MovementVelX/Z`; `MovementSpeed` is their magnitude). Owners coalesce to one `CmdSetLocomotionVelocity` per frame on change, and combat aim goes through `SubmitAim` (deduped). Once a controller publishes velocity, `AnimationOrchestrator` ignores its non-zero scalar Speed events, so the gait value cannot overwrite the strafe axes; a zero still lands (the can't-move path sends only Speed 0).
- **Combat walk→run surge:** predicted movement must ease world speed and anim `VelZ` together (`GetAnimSpeedForScale`). Do not let `ProcessPlayerInput` publish snapped Speed while predicted movement owns loco.
- **Batch rebuild while Editor open:** run the rebuild menu, or drop a **user-writable** `artifacts/force-rebuild-animator.flag` (root-owned flags fail to delete and skip rebuild). Batchmode cannot open a held project.
- **Do not flinch when collapsed/dead:** `TryApplyHitFlinch` requires `Ragdoll.Presentation == Locomotion` — never invent a parallel fall path from `Mix_ShoulderHitAndFall` here.
- **Stagger Additive is soft + Flinch, not Empty Additive:** `Empty Additive` is remapped to `Mix_InjuredHurtingIdle`. Slamming Additive weight to 1 on stagger shows hurting idle (looks like a flinch) then snaps off. Drive Additive via unmuted `Flinch` → gut and **lerp** weight (see `StaggerAdditiveWeight` / `TickAdditiveWeight`). Do not half-weight Full Body Override on stagger.
- **Never assign injury SyncVars on pure clients:** `HumanoidBodyStateBridge` runs `Update` everywhere and calls `SetInjuredArms`/`SetInjuredLeg`. Those SyncVars are server-only — writing them on a client spam-logs FishNet `Cannot complete operation as server when server is not active` (thousands/sec after embark). Guard with `IsServer` before assigning; clients apply via SyncVar OnChange.
- **`SetLocomotionMode(Idle|Walk|Run)` clears `IsFloating`:** while space-coasting, call `SetFloating(true)` only — never write gait modes. `SetFloating(false)` restores Idle when leaving Floating locomotion.
- **Client spawn stuck in Mix_Floating:** pure-client maps start empty and AOI often delivers non-plenum layers first. `GetSupportAt` must return `Unknown` for client occupancy-miss **and** client `!HasPlenum` — never local Unsupported. Server occupancy-miss is Unsupported only after `TileMapLoaded` (empty UnnamedMap must not pack Floating). Deep-space float on clients is SyncVar-driven (`ServerReconcileSpaceSupport`); Unknown keep-coast only while that SyncVar is already true. Structural register: [TECH_DEBT.md](../TECH_DEBT.md) §1.17.
- **Early Embark fall-through floor:** `Unknown` used to make `TryProcessSpaceFloat` return false → living path applied `CharacterController.Move(Physics.gravity)` with no tile colliders yet. Skip gravity on Unknown only while a downward raycast finds no floor; once colliders exist (or allow planar walk with no gravity), resume loco — a hard hold soft-locked movement after the map was visible but client `!HasPlenum` stayed Unknown. Same guard in `HumanoidPredictedMovement` when enabled. Hit 2026-07-26.
- **`HumanoidPredictedMovement` is disabled on `Human.prefab`:** space float and predicted ticks do not run until it is enabled; living Update path must carry space float (see `HumanoidLivingController.TryProcessSpaceFloat`).
- **`PublishSnapshot` used to no-op on pure clients:** owner now `ApplyOwnerSnapshot` so Floating hits the Animator without waiting on SyncVar; dedicated server still reconciles Floating via `ServerReconcileSpaceSupport`.
- **Space float is plenum absence, not atmos vacuum alone:** depressurized rooms with a floor still walk; no thrusters this pass — pure coast until plenum returns.
