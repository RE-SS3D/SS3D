# Map Editor systems views (Nov 2026)

The Map Editor gets an **Atmos** view and a **Power** view. Each colours every network, shows device state, traces a clicked network with live numbers, and marks clear problems. The same problems also appear in Map Check. Scope was settled in a grill on 2026-11-14: rounds 1–3 at the gameplay altitude, which produced [creative-mode.md](../design/creative-mode.md) §4, and rounds 4–5 at the implementation altitude (Q1–Q12 below; Q13 was settled while building Phase 0).

## Starting state (2026-11-14, `c82326f5`)

- **Network state is server-only.** Pipe networks live in `GasPipeNetworkRegistry` and power circuits in `ElectricitySubSystem._circuits`. Both are plain classes on the server. Clients have pipes and cables as tiles in their tilemap, but no networks, pressures or circuit numbers.
- **Network records are replaced on every pipe edit** (`RebuildAround`; [atmospherics](systems/atmospherics.md) Pitfalls). Ports cache network ids against `TopologyVersion`. Nothing gives a network an identity that survives an edit.
- **Debug queries exist server-side:** `AtmosCellDebugInfo` and `AtmosPipeDebugInfo` (used by `AtmosDebugController`), and `ElectricityDeviceDebugInfo` (`ElectricitySubSystem.Debug.cs`).
- **Debug views today:** `AtmosDebugController` is an IMGUI panel opened from F1, host-only, with turf and pipe colouring, inspection, gas spawning and region waking. `ElectricityDebugGizmoDrawer` draws circuit links in the Scene view only. Neither reaches a remote client or a release build's editor.
- **Overlay precedent:** `MapEditorAreaOverlay` draws synced room membership as client-local per-chunk meshes with a Resources shader. It switches on with Scripts → Rooms and off on other tabs. Room names show as UI Toolkit labels anchored near each room centre. Room membership and names reach clients through buffered `ObserversRpc`s on `AreaSubSystem`.
- **Layer visibility:** `MapEditorLayerVisibility` → `TileLayerVisibilityService` (client-only). The Cables, Gas Pipes and Disposal Pipes tabs hide Turfs and restore them on leaving, unless the user toggled Turfs meanwhile.
- **Pause:** each sim has a `SimulationChannel` with `Paused`. `AtmosSubSystem.SimulationPaused` wraps it, and `AtmosSubSystem.StepOnce()` runs one server tick. Electricity has no step. Every peer runs its own electricity channel (tech-debt P6.1). Opening the editor hides atmos *visuals* (`AtmosRenderContext.SetRenderingSuppressed`) but keeps the sim running.
- **Map Check:** `MapValidationReport.Issues` carries typed server-authored issues with an optional camera position (Locate). The mockup's atmosphere and power checks were never built ([tile](systems/tile.md)).
- **Select tool** opens an object's setup through its own interface ([object-setup-persistence](2026-11_object-setup-persistence.md)).

## Decisions

### Gameplay (premises)

[creative-mode.md](../design/creative-mode.md) §4 "Seeing what's connected" is the spec. In short:

- Two views, Atmos and Power. Each switches on with its Lower tab, and a toolbar toggle keeps it on from any tab. While a view is on, floors and upper objects dim like an x-ray.
- Colour per network. Device badges show state and flow direction. Rooms are tinted by their APC's circuit, and consumers get status dots.
- Select traces a network: everything else dims, the network gets a name label, and a panel shows live numbers and Locate.
- Room air is a sub-toggle. Pause and step are admin-only.
- Colours stay put through edits. A plain-language legend explains the markings.
- Problem markers use a fixed v1 list and also appear in Map Check (§8).

### Implementation

| # | Decision |
|---|---|
| Q1 | **The server computes everything**: network identity, colour ids, device states and problems. It sends them to clients that have the editor open. Rejected: clients rebuilding topology from their own tilemap. Problems must match the server-authored Map Check, and client reconstruction is the class of bug that host play hides. |
| Q2 | **Two data streams.** *Structure* (segment → view id, view id → colour and label, device badges, problem markers) is pushed to subscribed editor clients **on change**. A change is a topology version bump, a circuit rebuild, a device state change or a problem change, compared with what was last sent to *that* client (the atmos dirty-tracking pitfall). *Live numbers* are sent **only for the traced network**, to the client tracing it, at about 2 Hz. Room air reuses the existing atmos chunk-patch path, and only while its sub-toggle is on. Clients without the editor open get nothing. |
| Q3 | **One shared identity tracker** (pure C#), used by pipes and circuits alike. After a rebuild, each new network takes the view id of the old network it shares the most segments with. Ties go to the lower id. Others get fresh ids. The view id indexes a fixed colour palette and drives the label ("Supply 3", "Circuit 2"). |
| Q4 | **Rendering:** client-local per-chunk line meshes for runs, in the `MapEditorAreaOverlay` style. Room tint reuses that overlay with circuit colours. Instanced world-space quads draw device badges and problem markers. UI Toolkit draws the view toggle, trace panel, legend and trace labels, anchored like room-name labels. No Gizmos, no IMGUI ([agent-first-composition](2026-07_agent-first-composition.md) UI policy). |
| Q5 | **Problem analyzers are pure and server-side, one per domain.** Each returns typed issues with tile positions. The view snapshot and `MapValidationReport.Issues` both consume them, inside this effort, as their own phase. |
| Q6 | **Pause and step** go through an admin-gated ServerRpc (`MapEditorPermissions` with admin required, refused for sandbox players). It sets `Paused` on the atmos and electricity server channels and steps them, which means adding `ElectricitySubSystem.StepOnce`. Clients keep their local electricity tick, since visuals come from server SyncVars. The server **auto-resumes** when the pausing admin closes the editor or disconnects, and when the round ends. |
| Q7 | **Retire `ElectricityDebugGizmoDrawer`** once the Power view ships. **Keep the F1 `AtmosDebugController`** for its dev-only turf inspection, gas spawning and region waking, which are out of scope for an authoring tool. |
| Q8 | **Phase order:** shared base → atmos topology and badges → atmos tracing → power → problems and Map Check → pause, step and Room air. Each phase ships on its own. |
| Q9 | **Validation:** EditMode covers the tracker, analyzers, snapshot builders and change detection. One `mppm` step checks that a pure client in the editor receives structure and a traced network's numbers. A `visual` step runs only for overlay phases. |
| Q10 | **Code split.** Analyzers, snapshot builders and the network → segment mapping live in each domain (`Atmospherics/…/SystemsView/`, `Electricity/…/SystemsView/`) behind one small interface, `ISystemsViewSource`. | Q11 | **Select on a device while a view is on** both traces its network(s) *and* opens its setup as usual. A bare pipe or cable has no setup, so a click only traces. Turning a view on never changes what a click does to an object. |
| Q12 | **Milestone:** a new slice A10 in [map-authoring.md](../milestones/map-authoring.md), landing before A6 if possible. |
| Q13 | **Turning a view Off on Gas Pipes or Cables** also turns that tab's own view off, and it stays off until another sub-tab opens; a view pinned from the toolbar wins over the tab's own. Settled in Phase 0 (2026-11-14). |

## Phases

### Phase 0 — Shared base

1. `NetworkIdentityTracker` (Q3) with EditMode tests: merge, split, a full re-create with the same segments, and a tie.
2. `ISystemsViewSource`, plus the structure DTO and a delta against the last state sent.
3. `MapEditorSystemsView`: subscribe and unsubscribe per connection (editor open and current view), and per-connection last-sent tracking. Unsubscribe when the editor closes or the client disconnects.
4. View mode on `MapEditorViewModel`: Off, Atmos or Power; on by itself with Lower › Gas Pipes and Lower › Cables, and a toolbar toggle. X-ray layer handling goes through `MapEditorLayerVisibility` with the same restore rule the Lower tabs use.
5. Overlay renderer skeleton and the legend shell (collapsible, open the first time, remembered in `PlayerPrefs` like `MapEditorLastTab`).

`ISystemsViewSource` ships in Phase 0 with `View`, `StructureVersion` and `BuildStructure()` only; it gains `ReadLive(viewId)` in Phase 2 and `Analyze()` in Phase 4.

### Phase 1 — Atmos topology and badges

1. An atmos source: segment → network per line, manifolds included (`TryGetManifoldPort`), and devices from `AtmosPortRegistry`. Badge state covers vents and scrubbers (on, off, mode), valves (open, closed), and pumps, filters and mixers (direction, from their front and back). Two-network devices carry both view ids.
2. The overlay draws runs in their network colour, with real pipe colours dimmed. Hovering names the line.

#### Phase 1 deviations

- **Deviates from Q4 ("instanced world-space quads draw device badges")** because the area overlay shader has no instancing path. Badges are world-space quads in a per-chunk mesh, one render queue above the runs, rebuilt with their chunk. A few hundred badges cost one draw per chunk, so instancing would buy nothing yet. Phase 4's markers can follow the same path, or move both to instancing then.
- **Real pipe colours are dimmed by the x-ray, not covered.** The Atmos view dims the Gas Pipes layer to the x-ray alpha (its domain's own layer, `SystemsViewDomain.OwnLayer`), because the overlay's line offsets cannot match the real pipe meshes. That layer stays first to pick (`MapEditorViewModel.IsLayerPickable`), so Select and hover still hit pipes.

### Phase 2 — Atmos tracing

1. With a view on, Select traces the clicked pipe or device (Q11). The trace dims the rest, sets a label, and shows a UITK panel with pressure, temperature, mix, volume and the attached devices with Locate. A two-network device shows both sides, labelled.
2. The live stream (Q2): the traced view id per connection; values are re-read every ~0.5 s and sent only when they change.

#### Phase 2 notes

- **The live DTO is generic** (`SystemsViewLive.cs`): a message is `SystemsViewLive {View, TraceId, Paused, Networks[]}`, each `SystemsViewLiveNetwork {ViewId, Rows[], Devices[]}`, a row `{Label, Value}` and a device `{Key, Label, Detail}`. The server words and formats every value, so the panel stays domain-free, Phase 3 fills the same shape with supply, demand and charge rows, and a change below the shown precision is no change at all. `ISystemsViewSource` gains `bool ReadLive(int viewId, out SystemsViewLiveNetwork live)` (false means the network is gone) and `bool SimulationPaused`.
- **Trace state per connection** lives on the publisher's subscriber: the client's `TraceId`, up to `MaxTracedNetworks` (4: a manifold's four lines) view ids in the client's order, and the live message last sent. `RpcTraceSystemsView` (gated like `RpcSetSystemsView`) sets it; no ids ends it; switching views, closing the editor and disconnecting end it with the subscription. `PublishLive` runs on every second structure poll (0.5 s), right after `Publish`, so view ids match the structure just sent; it sends `TargetSystemsViewLive` only when the message differs from the last one sent to that client.
- **Stale traces.** A traced network keeps its view id through edits by the tracker, so the trace follows it. When an id disappears (the network went, or merged into one with a lower id), `ReadLive` returns false: the server drops it from the trace, and when none is left it sends one empty message and ends the trace. The client drops a side whose network leaves the structure or a live message, and ends the trace when none is left. The Atmos source re-maps view ids itself if an edit landed since its last build, so a network that only changed shape never reads as gone.
- **Pause hook.** `SystemsViewLive.Paused` comes from `ISystemsViewSource.SimulationPaused` (`AtmosSubSystem.SimulationPaused` for Atmos), the change detection includes it, and the panel shows a "Paused" tag (`systems-trace-paused`). Phase 5 only has to pause the channel.
- **Select picks for the trace separately.** Select's raycast stops at the first collider, which under the x-ray is usually the dimmed floor, a table or a wall, not the pipe the cursor is over. When the picked object is not part of the view, the trace reads the tile under the cursor on the overlay's own plane (`MapEditorCursorPick.TryGetPointedTile` at `MapEditorSystemsOverlay.Height`, which the hover readout now uses too), trying the view's own layer first (`TraceLayerOrder`). It never traces a tile other than the picked object's or the pointed one. Select still does what it did to the object it picked (Q11).
- **Rooms for Phase 3.** The pointed-tile fallback tries every layer, Turf and Plenum included, so the Power style's `TraceTargets` can answer a floor tile with a room target: the power source gives each room its own view id (a `SystemsViewNetwork` labelled with the room) and its `ReadLive` returns the APC's rows and the room's consumers as devices. No wire change is needed.
- **The panel floats beside the left column's top**, not under the legend as Q4's sketch put it, because the toolbar and an open legend leave no room under them above the library at 1080p.

### Phase 3 — Power

1. An electricity source: cable circuits, producers, SMES, APC → circuit, room → APC (`TryGetEffectiveApcForDevice`), and consumer status (powered, channel off, unpowered).
2. Room tint through the area overlay in circuit colours, with a hatched pattern for rooms that have no APC. Consumer dots.
3. A power trace panel: supply against demand, producer output, SMES charge and rates, APC charge, channels and breaker; clicking a room shows its APC and consumers.
4. Delete `ElectricityDebugGizmoDrawer` (Q7). Check that nothing else uses `ElectricityDeviceDebugInfo` before trimming it.

#### Phase 3 notes

- **Code.** `Electricity/SystemsView/`: `PowerSystemsViewSource` (server) reads `IPowerSystemsViewWorld`, which `ElectricitySubSystem.SystemsView.cs` implements over the server's `_registeredDevices`, `_circuitByDevice`, per-APC consumer index, `AreaSubSystem` rooms and `TryGetApcCircuitStats`, and registers on the hub from each server tick (as atmos does). Every peer ticks its own electricity channel (tech-debt P6.1), but the source exists only on the server, so it never reads a client's numbers. `PowerSystemsViewCodes` (wire codes), `PowerSystemsViewStyle` (client), `PowerSystemsViewDomain` (style, legend, Cables as own layer, hatch colour). The placeholder Power legend in `SystemsViewLegend` is gone.
- **Circuits.** Segments are HV cable tiles (`CableSlot` 0). Cable runs come from `ElectricCableConnectivity` (`EnumerateCableTiles`, `CollectCableRun`: the same walk that links grid devices, so Phase 4's problems and Map Check see the same runs), and the runs and grid devices the electricity graph puts in one `Circuit` are one network ("Circuit N"); grid devices joined side by side with no cable count too, a lone device on no cable is on none. The tracker's segments are cable tiles plus grid device places. The graph rebuilds a tick after a cable edit, so a cut first reads as one circuit for up to 0.2 s, then splits.
- **Badges.** Slot is `layer << 3 | facing` (`DeviceSlot`), because wall mounts on the two faces of one wall share a layer. Kinds: generator, solar panel, SMES (any non-APC storage), APC, light, other machine. A consumer's state is powered, its channel switched off at its APC, or unpowered (a broken APC reads unpowered, not channel off); ViewId is its APC's circuit and OtherViewId its room, so a circuit trace lights the machines its APCs feed and a room trace lights the room's.
- **Rooms.** The DTO gains `SystemsViewRoom {AreaId, ViewId, CircuitViewId, Flags}` in `SystemsViewStructure.Rooms`, two delta arrays and wire lines (`ProtocolVersion` 58 → 59). Each room is also a network, `RoomViewIdBase` (2^20) + its area id, labelled with its name, so a room traces through the unchanged trace RPC. The shared flag `SystemsViewRoom.Hatched` (no APC, or a broken one) keeps the client domain-free. The client tints rooms with a second `MapEditorAreaOverlay` built with a tint (`MapEditorAreaOverlay.Tint`, render queue 3999, under the runs): each room's tiles from the synced area cache in its APC's circuit colour at 0.22 alpha, or pale grey diagonal stripes. The Atmos view sends no rooms, so it never tints. The tint stays off while the Scripts › Rooms overlay is up, whose room colours painting needs. A trace dims rooms neither traced nor on a traced circuit; the panel and label colour a room by its circuit (`MapEditorSystemsViewClient.ColorOf`). The client compares each room's tint with the one last drawn, on a rooms delta or a focus change only, and the overlay rebuilds only the chunks of rooms whose tint changed (`MapEditorAreaOverlay.InvalidateAreas`); membership changes still rebuild it whole.
- **Tracing.** A cable traces its circuit; a generator or SMES its circuit; an APC its circuit and its room ("Circuit", "Room"); a consumer its room. A floor tile traces the cable under it if there is one, else its room, because Select usually picks the dimmed floor: to trace a room, click a floor with no cable, a machine or the APC. `ReadLive` on a circuit gives Supply, Demand (what its APCs draw for their rooms), Balance, Stored, Cable and every grid device (an SMES with its rate in or out from the energy change over server ticks between reads); on a room its APC (circuit, condition, charge, each breaker with its load, load, grid draw, state) and the APC and machines as devices. `SimulationPaused` reads the server electricity channel's `Paused` (`ElectricitySubSystem.SimulationPaused`); Phase 5 adds the setter and `StepOnce`. Paused with no tick since the last read, an SMES reads "paused", not its last rate.
- **Change detection.** `ElectricitySubSystem.SystemsViewTopologyVersion` moves on a cable placed or cleared, a circuit graph rebuild, `ClearRegisteredDevices`, an area index invalidation, and the channel's `Resumed` (the template-load risk below). Device state is announced by `PowerStateVersion` (static, server): bumped where a consumer's `PowerStatus` is written (`Circuit`, `AreaApcPowerDistribution`), on an APC's breakers or condition changing (`ApcController.RefreshAfterChannelsChange`), an SMES's `IsOn`, and a device registered or removed. A poll with neither version moved re-reads only producers (solar output follows the sun with no single write); otherwise every device and room is compared field by field with the last poll, keyed by the device or room id (no hashing). Rooms are compared every poll (82 on MetaStation). A moved topology rescans cables; a grid device that came, went or moved re-joins circuits without a rescan; a state change does neither.
- **Q7 done.** `ElectricityDebugGizmoDrawer` was a plain MonoBehaviour component on `NetworkSystemsHub.prefab`, so removing it moves no NetworkBehaviour index. A one-shot `PrefabUtility` recipe (load contents, destroy the component, save; deleted with the script, tier C) removed it; the hub diff is that component's block and its component entry, plus Unity rewriting NapalmSubSystem's `m_Name:` to its canonical `m_Name: ` (the one line of 38 without the trailing space). The script, `ElectricitySubSystem.Debug.cs` (`ElectricityDeviceDebugInfo`, used only by the drawer), `ElectricityDevSettings` (only its menu toggle) and the `HubComponentTypes` entry are gone.
- **Visual pilot.** `MapEditorSystemsPilot` turns Power on after the Atmos steps (`MapEditorSystemsPowerPilot`, its own class under the 900-line class cap): overview (`20-power-overview`), a cable trace on the circuit with the most grid devices (`22-power-circuit-trace`), a floor trace in the room with the most machines (`23-power-room-trace`), then, because the shipped stations give every room an APC, it smashes the APC of a small room (round state only, repaired after) for `21-power-hatched-room`.

### Phase 4 — Problems and Map Check

1. An atmos analyzer: open pipe end; a device on no pipe; a vent or scrubber whose network has no source or no sink; a powered atmos device in a room with no power.
2. A power analyzer: an APC on no cable; a circuit with no producer or storage; demand above supply; a room with consumers but no APC; an SMES on no circuit.
3. Markers in the view. Typed `MapValidationReport.Issues` with Locate; severity is a warning, never a round-start block. Plain-language strings shared with the legend.

#### Phase 4 notes

- **Code.** Shared: `SystemsView/SystemsViewProblems.cs` (`SystemsViewIssue {Id, Category, Title, Body, EntryKey, Position, Markers[]}`, `SystemsViewProblemKind {Code, Name, Words}`, marker slot, drawing and legend lines), `ISystemsViewRooms` (a device's room and whether it has power), `ISystemsViewSource.Analyze()` and `AnalysisCurrent`, `SystemsViewPublisher.Analyze(into)` and `AnalysisCurrent`, and the shared `SystemsViewProblems.Issue`, `RoomName` and `IndexOnTile` helpers. The APC palette key is `MapValidator.ApcEntry` alone. Atmos: `AtmosProblemAnalyzer` (pure; input `AtmosProblemInput` of pipes and devices), filled by `AtmosSystemsViewSource`; `AtmosPortControllerBase.NeedsPower`. Power: `PowerProblemAnalyzer` (pure; `PowerProblemInput` of devices and rooms), filled by `PowerSystemsViewSource`; its poll state (`PowerSeen`, `PowerSeenRoom`, `PowerRate`, `PowerCircuitNetwork`, nested types of the source until now) moved to top-level types in `PowerSystemsViewSeen.cs`, because `ClassSizeRatchetTests` counts a nested type's lines toward the class holding it and the analysis input building would have taken the source past the 900-line cap; `IRatedPowerProducer` on `BasicPowerGenerator`, `FuelPowerGenerator` and `SolarPanel`, `IRatedPowerConsumer` on `MachinePowerConsumer`, `PowerSystemsViewCodes.IsSupply`; `ElectricitySubSystem.SystemsViewRooms` implements `ISystemsViewRooms` for the atmos side. Map Check: `MapValidator.AddSystemsIssues`, called by `MapValidationService.Validate` through the hub's publisher.
- **One rule, two readers (Q5).** Each source caches its analyzer's issues; `BuildStructure` puts them in as markers (`SystemsViewMarker.IssueId` is the issue's id) and Map Check adds the same issues as warnings with Locate (`HasPosition`, the device's or tile's world spot), never a round-start block. Map Check reads them whether or not anyone watches a view. Round start passes `includeSystemsViews: false`: they are warnings only and right after a template load the networks are not rebuilt yet. So a refused round's message (`MapValidationReport.Describe`) no longer lists the "device on no pipe" and "No APC" warnings it used to; it lists the blocking errors as before, and the map editor's Map Check shows the warnings. Judged not worth running the analyzers at round start, when atmos has not initialised on the new map. An id already in a report is not added twice.
- **Change detection.** The analysis runs again only when something it reads changed. Atmos: a run rebuild or re-link (topology, or a device added, removed, moved or turned), a meter, injector or line fill coming or going, or `ISystemsViewRooms.Version` moving with a powered device's room or its power changing. Power: a topology move or circuit join, a device added or removed, one that moved or changed room or APC, or a room's APC changing. Each also moves `StructureVersion`, so the publisher rebuilds; a switch, mode, status dot or breaker flip moves only its badge and reuses the cached issues (`LastAnalyzed` in the tests). A cold `Analyze()` of both sources on MetaStation is 110 ms (including the Atmos source's first walk of every network), classic-ministation 0.1 ms.
- **Waiting for the networks after a load.** `ISystemsViewSource.AnalysisCurrent` is false while the state an analyzer reads lags the map: the power graph is dirty (`IPowerSystemsViewWorld.CircuitsCurrent`, `ElectricitySubSystem._graphIsDirty`: it rebuilds a tick after a template load or cable edit, and until then `CircuitOf` answers null, which read as every APC and SMES on no circuit), or atmos is not ready on the map. A source that isn't current reports nothing and stays stale; the graph's rebuild moves the topology (and atmos becoming ready is polled), so the next build and `Analyze()` give the real problems. Map Check remembers each client it sent a report to while any source wasn't current (`MapEditorSystemsView.cs`, `AwaitSystemsForValidation`) and sends that client's report again on the first server update once all are, so the report after a Load or New Map fills in by itself.
- **No protocol change.** Markers have been on the wire since Phase 0. A marker's slot is the problem kind's code in the high five bits and a sub-slot in the low three: the line, for an open end, or the device's place among those on its tile (west to east, then by layer), so two kinds of problem on one tile, or two devices on one tile with the same problem (an APC on each face of a wall), each have a marker key of their own. The hover names each kind once, in the legend's words.
- **Drawing.** *Deviates from Q4 ("instanced world-space quads draw … problem markers")* as Phase 1's badges do, for the same reason: markers are quads in the badge chunk mesh, drawn after the badges, one per tile however many problems it has, in the tile's north-east corner so the badge under it stays readable: a dark-edged red diamond with a white bar and dot. A trace never dims a marker. The legend adds "A red diamond marks a problem…" and one line per kind, `Name: Words.`, the same words Map Check's body uses.
- **Strings shared with the legend.** Each kind has a `Name` and number-neutral `Words`; the legend line is `Name: Words.` and every Map Check body contains the same `Words` (`EveryBody_CarriesItsKindsLegendWords` in both analyzer tests), after a title that names the spot and the count, and before the fix. Atmos (category "Atmos"): `open-end:<line>:<x>:<y>` "Open pipe end: the pipe stops here, joined to nothing."; `pipe:<kind>:<x>:<y>` "Device on no pipe: it does nothing until it is on a pipe it can use."; `no-source:<x>:<y>` "Vent with nothing feeding it: nothing puts gas into this network, so its vents can't fill their rooms."; `no-sink:<x>:<y>` "Scrubber with nowhere to send gas: nothing takes gas out of this network, so its scrubbers soon stop cleaning the air."; `atmos-power:<area>` "Device in a room with no power: its room has no working APC, so a device there that needs power does nothing." Power (category "Power"): `apc-cable:<x>:<y>` "APC on no cable: its room runs on the APC's own cell until it's flat."; `circuit-source:<x>:<y>` "Circuit with no generator or storage: nothing feeds it, so its rooms go dark once their APC cells run flat."; `circuit-demand:<x>:<y>` "Circuit that needs more than it gives: its rooms can draw more than its generators, solar panels and SMES units supply at most." (then "up to 5.9 kW against at most 5.0 kW"); `no-apc:<area>` "Room with machines but no APC: nothing here gets local power."; `smes-circuit:<x>:<y>` "SMES on no circuit: it can't store or give power." A network or circuit issue is named by its first vent, scrubber or APC west to east and marks each of them; a room issue by its first device. Two APCs on one wall tile with no cable share an id (`apc-cable:<x>:<y>`), so Map Check lists them once, while the view marks both.
- **Two Map Check rows moved, and what changed in them.** "Device on no pipe" (`pipe:*`) and "No APC in <room>" (`no-apc:*`) were already in `MapValidator.AddRoomDeviceChecks`. They are v1 problems, so they moved into the analyzers (Map Check would otherwise list each twice); `RoomDeviceRecord` lost `HasPipe` and `RoomHasApc`. Their ids and titles are unchanged. What changed: (1) the `pipe:*` bodies now carry the legend's words ("…has no Supply or Mixed pipe on its tile, so it does nothing until it is on a pipe it can use. Run one under it."), where a meter's or injector's said "so it has no line to work on" and the rest "so it can't move any gas"; (2) `no-apc:*` moved from category Atmos to Power; (3) the old `no-apc` fired for a room holding any `RoomDeviceKind` (a vent, scrubber, pump, valve, filter or mixer, meter or injector, air alarm, light or light switch, APC) with no APC, and now fires for a room holding any registered `IPowerConsumer` (any machine, door or light). So a room whose only devices have no power consumer of their own (meters, injectors, manual valves, a light switch where its prefab has none) no longer warns, and a room with only, say, a vending machine now does. Kept: nothing in such a room needs local power, which is what the row says. The analyzers cover meters, injectors and line fills as the old `pipe:*` row did.
- **Open pipe end.** A pipe joined on at most one side (its `Links`), on a tile with no vent, scrubber, meter, injector or line fill (a run filled from its last tile is meant to stop there). A run that reaches such a device's tile ends there on every line: stations run Supply and Waste side by side, and the first rule (only the device's own line ended) marked 10 harmless stubs on classic-ministation, one per room device. Manifolds, pumps, filters, mixers and valves are already links. *Deviates from creative-mode §4's example wording ("gas leaks out here")* because the simulation doesn't leak gas at a pipe end today; the marker says what is true.
- **Source and sink.** A vent's network needs something putting gas in; a scrubber's needs somewhere for it to go. Sources: a scrubber (it takes room air in, as a chamber intake does), the outlet of a pump, filter or mixer, a filter's side (the gases it lets out), either side of a valve, a line fill. Sinks: a vent (into its room or out to space), the inlet of a pump, filter or mixer, a mixer's second inlet (its side), either side of a valve, an injector. State never counts (a pump switched off, a valve closed): the round switches them, so "off" is not a mistake. Only the network itself is judged, never what feeds the pump's other side, which would be a guess about intent.
- **Room power.** "No power" is what the Power view hatches: the room has no APC, or a broken one (`ISystemsViewRooms.HasPower`, answered by the electricity side from `AreaSubSystem.TryGetAreaApc` and `BreakableDevice`), so the atmos analyzer reads only that interface. An APC on no cable still powers its room from its cell, and the Power view marks it instead. A device "needs power" when it has a power consumer (`NeedsPower`). A device outside every room is Map Check's existing "outside every room" row, not this one. One issue per room, a marker on each powered device.
- **Demand above supply.** An authoring check, not a reading: demand is every consumer fed by the circuit's APCs drawing its most with every channel on (`IRatedPowerConsumer.RatedPowerKw`: a machine's in-use or idle draw, whichever is more; a consumer without a rating, its constant `PowerNeeded`); supply is every producer's rated output (`IRatedPowerProducer.RatedPowerKw`: a fuel generator's prefab output, switched on or not; a solar panel's peak, sun or no sun) plus every SMES's `MaxDischargeRateKw`, charged or not, switched on or not. Demand within 0.05 kW of supply is enough. None of these moves with the sun, a switch, a machine going into use or a charge (`DemandAboveSupply_ReadsRatings_NotTheMomentsOutputOrDraw`), and the analysis is not re-read on a state change, so the marker doesn't flicker. A circuit with no generator or SMES is the other problem, never both; a circuit is only judged when an APC is on it (a cable with nothing that wants power is harmless).
- **APC and SMES on no cable.** Their circuit view id is 0: no cable on their own tile and no grid device joined to them, the rule `ElectricCableConnectivity` links grid devices by. A broken APC still counts as an APC for "no APC".
- **Shipped maps.** classic-ministation: 3 Atmos open ends (a Supply run west of the chamber ending at (-13, -8) in space, a Waste run ending at (-9, -8), and a Mixed stub one tile past the chamber intake at (2, -11)), nothing else; with the existing "1 vent outside every room" Map Check now lists 4 warnings and the map still starts. The MetaStation measuring copy (`Metastation v2`, imported from SS13, which can't start a round): 503 open ends, 469 devices on no pipe, 3 vent networks nothing feeds (one of 30 vents), 7 scrubber networks with nowhere to send gas, 80 APCs on no cable, 1 circuit with no generator or storage, 1 SMES on no circuit, nothing in rooms with no power and no circuit short of power. The 469 are the pre-Phase 4 rule unchanged. Sampled open ends and APCs are real under the game's own rules: SS13 sets a vent beside its pipe's end and an APC beside its cable's, where SS3D attaches both only on their own tile, so the pipe end, the vent and the APC are each marked. That is the import, not the rule.

### Phase 5 — Pause, step and Room air

1. Pause and step (Q6), including `ElectricitySubSystem.StepOnce` and auto-resume.
2. The Room air sub-toggle: subscribe that client to atmos chunk patches and lift `AtmosRenderContext.SetRenderingSuppressed` *only* for the pressure tint, never the fog or wind visuals the editor hides.

#### Phase 5 notes

- **Code.** Shared: `SystemsView/SystemsViewSimulation.cs` (`SystemsViewSimulationAction` Pause, Resume, Step; `ISystemsViewSimulation` {`SimulationPaused` get/set, `StepOnce()`}; `SystemsViewSimulationControl`, pure: `Apply(clientId, mayControl, action)`, `Release(clientId)`, `ResumeAll()`, `Reconcile()`, `PausedBy`). Hub: `MapEditorSystemsViewServer` (plain class, both server jobs of this phase: the pause with its gate, who is told and when it lifts, and Room air's resync; `Update` runs each server frame), exposed as `MapEditorSubSystem.SimulationPause`; `MapEditorSystemsView.cs` holds only the RPCs: `RpcSystemsSimulation(action)` (ServerRpc), `TargetSystemsSimulation(paused, mayControl)`, `RpcSetSystemsRoomAir(on)` (ServerRpc). `AtmosSubSystem` and `ElectricitySubSystem` implement `ISystemsViewSimulation`; `ElectricitySubSystem.Channel` is the process's channel, like `AtmosSubSystem.Channel`. `SimulationChannel.Step()` fires one counted tick now, paused or not, and nothing while a world suspension holds the channel; `AtmosSubSystem.StepOnce()` fires the channel too (the F1 debug step included), so air alarms sample with the step. Client: `MapEditorRoomAirOverlay`, `UI/MapEditorSystemsSimBar` (`systems-sim`: `systems-room-air`, `systems-sim-paused`, `systems-sim-pause`, `systems-sim-step`), `MapEditorViewModel.SystemsRoomAir`, `SystemsSimulationPaused`, `MaySystemsSimulationControl`. Atmos: `AtmosRoomAirPalette`, `Visualization/AtmosChunkResync`, `AtmosSubSystem.BeginChunkResync` / `EndChunkResync` / `SendChunkResync`, `TargetApplyChunkPatch`, and `AtmosSubSystem.SetRoomAirRequested` (the one entry point for `AtmosRenderContext.FullAtlasRequested`). `ProtocolVersion` 59 → 60.
- **The admin gate.** `MapEditorPermissions.MayControlSimulation(conn)`: the editor is open (`IsEditing`), the authorizer lets the player in, and they are the host or an Administrator by role (`HostOrAdministrator`, which also defines `IsSandboxPlayer`, so a sandbox player is refused by construction). The role check is its own, not the editor authorizer's: the open-build authorizer (`-sandbox`, and `mppm:systems-view`'s `editor_for_clients`) lets every player into the editor, and a later Builder authorizer would too. The server sends each client the state and its right on editor open, and every editor user the state on each change; a refused request gets a toast and the state again. Non-admins see no Pause or Step; everyone in the editor sees PAUSED. Listed `AuthorityCheck.Admin` in `ServerRpcAuthorityAuditTests`; Room air is `MapEditorPermission`.
- **Pause and step.** A pause sets `Paused` on the server's atmos and electricity channels, holding only those it paused itself: one already paused by something else (the F1 debug pause) stays paused when the admin resumes. A pure client's own electricity channel is never touched: its device visuals follow the server's SyncVars. On a host the one process's channels are the server's. Step runs only while paused and fires each channel once (`SimulationChannel.Step`, counted in `TickCount`), so a step is exactly one atmos and one electricity tick, an SMES rate reads across it rather than "paused", and the live stream's next read sends the new numbers. A pause while paused hands it to the newer admin's editor.
- **Lifting the pause.** It lifts, resuming only what it held, and every editor user is told: when the pausing admin's editor closes (`RpcSetEditorOpen`) or they disconnect; when `RoundStateUpdated` leaves Ongoing; when the server stops (the electricity setter writes `ElectricitySubSystem.Channel`, which outlives `OnStopNetwork`, so the order of the stops doesn't matter); when a world suspension starts (a map load, clear or import); and when a simulation runs again under it (`Reconcile`: F1's resume, or a station template restore, whose `AtmosSubSystem.DisposeSimulation` unpauses atmos), so electricity is never left paused alone and the editor never says PAUSED while a simulation runs. Automation never leaves the simulations paused: `SystemsViewAutomation.Reset` and the pilot's `Reset` resume.
- **Room air.** The sub-toggle sits in the bar while the Atmos view is on. It is off by default and goes back off when the editor closes (`MapEditorSystemsViewClient.Stop`), as creative-mode §4 has it ("off by default so it doesn't bury the pipes"). The tint reads the CPU copy of the atmos snapshot (`AtmosRenderContext.Snapshot.PressureData` and `MaskData`), so the editor's `SetRenderingSuppressed(true)` is never lifted: the fog, glow, distortion and wind stay hidden, and the pressure tint is a client-local overlay in the area overlay's style (render queue 3998, under the runs). *Deviates from the phase line ("lift `AtmosRenderContext.SetRenderingSuppressed` only for the pressure tint") because* no pressure tint existed to lift it for: the renderer feature's passes are fog, glow and distortion, and its Pressure debug view paints the screen opaque; the overlay reaches the same result with suppression left on. Only simulated cells are tinted (not space or walls), in 64 steps of 4 kPa (`AtmosRoomAirPalette`: red with no air, amber thin, green about 101 kPa, blue then purple above); the overlay re-reads the snapshot twice a second and rebuilds only chunks where a tile changed step. The legend has a Room air line.
- **Room air's patches (Q2).** *Deviates from Q2 ("Room air reuses the existing atmos chunk-patch path, and only while its sub-toggle is on") because* that broadcast is an `ObserversRpc` that already reaches every pure client, editor or not; only the new targeted resync is gated by the toggle. The broadcast sends only what changed since it last broadcast, from awake cells, so a client that joined after the station settled never gets its calm rooms. Turning Room air on sends that client every chunk once (`AtmosChunkResync`, `TargetApplyChunkPatch`, at most the broadcast's 16 patches per 0.25 s, taking turns between clients), after which the broadcast keeps it current like any client. Another "on" while it runs or after it finished is ignored; only off then on sends the station again. A station template restore sends the new station to every client with Room air on once atmos is ready. The resync's patches are built without advancing the broadcast's visual-fire decay (`AtmosChunkPatchBuilder.Build(advanceFire: false)`), so they change nothing for other clients. A host reads its own atlas, which normally covers only its player's area of interest, so Room air widens it to the whole station (`AtmosSubSystem.SetRoomAirRequested`, which also publishes at once when paused). The full upload costs about 10 ms a tick on MetaStation (the atmospherics host-upload pitfall), only while Room air is on a host; the request is cleared when Room air goes off, the editor closes and the hub is destroyed.
- **Validation.** EditMode `SystemsViewSimulationTests` (the gate on bools and on connections, the hub half's toasts, broadcasts and lifts, F1 in both orders, a channel step, the bar, the resync, Room air's steps) and an SMES rate read across one step in `PowerSystemsViewSourceTests`. `mppm:systems-view` refuses the client's pause and follows the host admin's pause, steps and editor close through the client's trace. `visual`: `MapEditorSystemsAirPilot` (`30-atmos-room-air`, `31-atmos-paused-trace`).

## Risks to check while building

- **MetaStation traffic and mesh cost.** A full structure snapshot on first open could be large. Measure it, and fall back to chunked sending, oldest first, as the atmos patches do, if it passes the existing patch budget. *Phase 1:* MetaStation's first open is 45,878 B (5,759 runs, 54 networks, 513 badges), one send under the 48 KB `MaxBytesPerSend`; larger deltas go out over several polls, removals and labels first. *Phase 3:* the Power view's first open on MetaStation is 49,820 B (3,615 cable tiles, 47 circuits, 82 rooms, 1,778 badges of which 1,685 consumers), just over the budget, so two sends; classic-ministation's is 2,139 B.
- **Ports resolve their network lazily** against `TopologyVersion`. The source must read the current registry, not port caches, or a just-edited device shows its old network for a tick.
- **The electricity graph rebuild** after a world suspension (`Resumed`) must also bump the structure, or the Power view goes stale after a template load. *Phase 3:* `Resumed` and every graph rebuild move `SystemsViewTopologyVersion`, which the source compares each poll (`AWorldResumption_MovesTheTopology_SoTheStructureIsRebuilt`).
- **A device-state change has no single event.** Each badge-carrying device needs a cheap server-side "changed" signal, or the source polls on the atmos tick and compares. *Phase 1:* the Atmos source compares each device with its last poll (4 Hz, only while watched). On MetaStation, in the editor: a cold build walking all 54 networks takes 90 ms and a warm one 2 ms; a device added or removed re-links only the pipes beside it, 5.5 ms (4 pipes, no network walked), where it first re-walked every network (92 ms). *Phase 3:* the Power source re-reads every device only when the topology or `PowerStateVersion` moved, keeping each device's tile object, kind, name, room and APC between topology moves; otherwise it reads producers and rooms. On MetaStation, in the editor: an idle poll 0.10 ms (5.9 ms when it read every device each poll, 10.8 ms before the caches), a full re-read after a state change about 6 ms for ~1,800 devices, a cold build (Wire scan, circuit join, every device and room read) 53–69 ms, a warm build 1–3.6 ms. Classic-ministation: cold 30 ms, poll 0.4 ms before the state version.
- **Pausing while an `mppm` client is mid-trace:** live numbers stop changing; the panel should say "Paused" rather than look frozen. *Phase 2:* the live message carries `Paused` and the panel shows it. *Phase 5:* the admin pause sets it, a step is one counted tick of each channel so the next read sends fresh numbers, and `mppm:systems-view` watches a client's trace through it.
